# 통합 파이프라인 추가 점검 — 2026-09-15

기준 커밋 `64bd546` 이후 점검. 과거 130/139개 시나리오를 되살리는 작업이 아니다.
현재 165개/435턴 시험지는 수정하지 않았다. 아래는 통합앱의 실제 연결부에서 확인한 결함이다.
각 결함이 원본 저장소에 없었는지까지 확인하지 않은 것을 이식 누락이라고 단정하지 않는다.

## 수정 사항

- 최종 답변 무시: 토큰을 한 번이라도 받으면 `FinalMessage`를 무시했다.
  이제 최종 이벤트가 스트리밍 임시 답변을 교체한다.
- 엔진 자체 취소: `CancellationException`이 발생하면 busy/승인 상태 정리가 실행되지 않았다.
  현재 세대의 취소만 상태를 해제하고 이전 검색 결과도 무효화한다.
- 새 대화 경합: 엔진 초기화가 끝나기 전에 새 질문을 받아 나중에 대화가 지워질 수 있었다.
  초기화 중 전송을 차단하고, 초기화 실패 시 성공적으로 재시도하기 전까지 구세션을 재사용하지 않는다.
- 앱 재진입 경합: 액티비티 종료 시 별도 코루틴으로 초기화해 새 화면의 턴과 겹칠 수 있었다.
  종료/재진입도 같은 ChatSession 초기화 게이트를 사용한다. 메인 스레드 `runBlocking`을 제거했다.
- 화면 대화 삭제: 말풍선만 비우고 실행 중인 이전 턴은 유지했다.
  이제 턴 취소와 세대 변경을 함께 적용한다.
- 늦은 검색 결과: `clear()` 이후 완료된 이전 검색이 새 검색 결과를 덮어썼다.
  검색 시작 세대를 원자적으로 확인한 뒤 같은 세대에만 결과를 게시한다.
- 명함 탭과 채팅 혼선: 두 화면이 채팅 증거 기록용 backend까지 공유했다.
  같은 검색 엔진/DB를 사용하되 명함 탭은 채팅 결과 기록기를 거치지 않는다.
- 검색 영구 비활성화: 초기화/벡터 저장이 한 번 실패하면 availability가 계속 false가 되어
  다음 턴에서 검색·조회·개수 도구를 실행할 수 없었다. 구성 여부와 마지막 실행 성공 여부를 분리했다.
  다음 사용자 요청에서 초기화를 재시도하며 필수 모델 검사와 실패 전파는 그대로 유지한다.
  자동 무한 재시도나 키워드 폴백을 추가하지 않았다.
- OCR 필수 모델: KIE 또는 글줄 방향 모델 로드 실패에도 부분 파이프라인이 실행됐다.
  이제 해당 모델도 필수이며 실패 시 촬영 인식을 차단한다. 휴리스틱 대체 경로를 제거했다.
- OCR 자원 수명: IO 인식과 화면 종료의 close가 겹칠 수 있었다.
  read/close를 직렬화하고 close를 멱등 처리한다. 화면 종료의 자원 정리는 IO에서 수행한다.
  로드 후 디스패처 복귀 중 취소되어도 생성한 엔진을 잃지 않도록 소유권을 정리한다.
  KIE 세션 옵션 및 모델 쌍 검증 실패 시의 자원 누수도 수정했다.
