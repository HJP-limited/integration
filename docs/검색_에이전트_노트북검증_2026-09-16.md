# 검색·에이전트 분리 및 노트북 실제 모델 검증

## 처리 원칙

화면을 별도 앱으로 나누지 않고 현재 턴의 실행 권한을 구분한다. 대화에서 인물은 기억하되 이전 메일·일정·수정 요청을 새 검색의 실행 권한으로 사용하지 않는다.

| 현재 요청 | 실행 경로 | 답변 |
| --- | --- | --- |
| 이름·직업·조건 검색 | 필수 실제 검색 → 결과 저장 | 도구가 없는 Gemma 세션에서 결과 설명 |
| 특정인 전화번호·회사·부서 조회 | 검증된 명함 ID의 get_contact 또는 검증된 표시 정보 | 정확한 DB 값을 표시, 불필요한 생성 생략 |
| 메일·문자 작성 | 대상·주소 검증 → open_compose | 실행 결과에 근거한 설명 |
| 일정 작성 | 날짜·시간·대상 검증 → create_calendar_event | 작성 화면 열기와 저장 완료를 구분 |
| 명함 수정 | 대상·필드·값 검증 및 사용자 승인 → update_business_card | 실제 수정 결과에 근거한 설명 |

일반 검색 턴에서 모델이 작업 도구를 요청하더라도 워크플로 정책이 차단한다. 조회 설명용 Gemma에는 도구 목록 자체를 제공하지 않는다. 모델 없이 답하는 정확한 필드 조회를 'Gemma 추론 성공'으로 세지 않는다.

## 확인하고 수정한 원인

- `문지영씨 전화번호`, `부서는`: 동사 없는 필드 조회가 일반 생성으로 빠짐. 말끝의 필드 명사/조사를 조회로 처리.
- `데이터분석가 누구 있지`: 저장 직함의 띄어쓰기 차이와 사람을 묻는 표현 때문에 검색 의무가 빠짐. 저장소 직함 비교의 공백 정규화 및 사람/직업 질의 보완.
- `아니 문지영으로 바꿔줘`: 이름 필드 수정과 대화 대상 변경을 혼동. 검증된 이름만으로 구성된 대상 변경을 새 명함 조회로 처리.
- 같은 사람의 이름을 다시 말하면 directoryLookup이 기존 선택 ID를 제외해 재검색. 같은 이름도 정상적으로 새 필드 조회에 연결.
- 이름을 정확히 검색해도 의미적으로 비슷한 다른 이름이 top-5에 혼입. 저장된 이름과 완전히 같은 검색어는 해당 ID들로 결과를 제한. 동명이인은 모두 유지하며 한 명을 임의 선택하지 않음. 실제 임베딩은 계속 필수이며 키워드 폴백이 아님.
- 모델이 검색 없이 '없다'고 답하는 것을 통과시키지 않음. 검색 의무를 먼저 실행하고 결과를 Gemma에 제공.
- 검색 여부를 결정하는 불필요한 모델 생성 1회를 제거. 결과 설명에만 Gemma를 사용하고 간결한 목록을 요청.
- 조회 답변에는 현재 질문과 이번 검색 결과만 제공하여 이전 검색 인물이 섞이지 않게 했다. 도구 실행 후 다음 턴에는 네이티브 대화를 정규 세션 기록으로 재구성한다.
- 문자에 모델이 붙인 제목만 제거하고 수신자·본문 검증은 유지한다. 문자 완료 안내를 메일로 잘못 표시하지 않는다.
- 참석자 없는 새 일정까지 이전 검색 후보 선택을 요구하던 문제를 수정했다. 현재 요청이 사람을 참조할 때만 이전 후보 의무를 적용한다.
- 노트북도 앱과 동일한 공식 모델 검증·대화 예산·사전 검사와 명함 수정 후 즉시 재임베딩을 사용한다.

## 노트북 사용법

프로젝트 루트의 PowerShell에서:

```powershell
.\scripts\run_desktop_chat.ps1
```

최초/소스 변경 시 실행기를 빌드한다. 빌드된 최신 실행기를 그대로 쓸 때만 `-SkipBuild`를 사용한다.
질문을 한 줄씩 입력하며 `:reset`은 새 대화, `:quit`은 종료다. 같은 세션으로 이어지는 질문과 도구 이름·소요 시간·전체 답변을 볼 수 있다.

보고된 실패 질문 8개를 실제 모델로 일괄 실행하고 자동 판정하려면:

```powershell
.\scripts\run_desktop_chat.ps1 -Regression
```

문자 → 검색 → 참석자 없는 일정 → 검색 → 전체 명함 수의 추가 검증:

```powershell
.\scripts\run_desktop_chat.ps1 -Regression -Suite tools
```

실행 중인 채팅이 끝나기 전에는 다른 창에서 `installDist`를 재실행하지 않는다. 실행 중 배포 JAR를 덮어쓰면 클래스 로딩이 실패할 수 있다.

`eval/device_user_regressions_2026-09-16.json`의 도구 허용/필수 목록, 정확한 명함 ID, 전화번호·회사·부서 값 및 직업 근거를 검사한다. 이전 검색 인물을 이번 결과처럼 답해도 실패한다. 원시 로그는 `build/desktop-user-regression.log`에 남긴다. 단위 테스트의 모의 모델 결과와 구분한다.

기본 읽기/쓰기 대상은 `build/hjp-desktop.db`다. 빈 DB에는 앱과 같은 기본 명함 시드를 넣는다. 휴대폰에서 새로 촬영한 명함이 자동으로 노트북에 동기화되지는 않는다. 테스트 DB를 분리하려면 `HJP_DESKTOP_DB`를 지정한다. 명함 수정은 기본 거절하며 CLI의 `--yes`는 테스트 DB 수정 승인을 명시적으로 허용하는 옵션이다.

메일·일정은 앱의 실제 계약·코덱·검증 코드를 공유하되 마지막 외부 화면 호출만 `SIMULATED`로 기록한다. 메일이 전송되거나 일정이 저장되는 테스트가 아니다. Gemma와 임베딩은 모의 모델을 쓰지 않는다.

### 필수 환경

- 현재 PC의 Temurin Java 21, Python LiteRT-LM 네이티브 런타임.
- 배포 Gemma `gemma-4-E2B-it.litertlm`: SHA-256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`를 검사.
- EmbeddingGemma ONNX 모델·외부 데이터·토크나이저. 누락/로드 실패/추론 실패 시 중단.
- 기본 모델 위치는 프로젝트 옆 `HJP_limitededition-main/models`.
- 다른 환경은 `HJP_DESKTOP_JAVA_HOME`, `HJP_PYTHON`, `HJP_GEMMA_MODEL`, `HJP_EMBED_MODEL_DIR`로 지정.

이 PC의 Android Studio JBR은 MSVC 14.29를 포함해 ONNX DLL 초기화에 실패했다. 설치된 Temurin 21(MSVC 14.40)로 실행하며 시스템/JDK DLL은 변경하지 않는다. 해당 종류의 충돌은 [ONNX Runtime 유지관리자 설명](https://github.com/microsoft/onnxruntime/discussions/23971)과 부합한다.

노트북 임베딩 DB는 여러 행을 한 트랜잭션으로 저장한다. 매 행마다 디스크 반영하던 초기화 지연을 줄였다. 네이티브 모델 로그는 `build/desktop-gemma-cache/runtime.log`에서 확인한다.

## 검증 범위와 한계

- 앱과 동일한 agent-core, 검색 코드, 연락처 도구, 세션·라우팅·워크플로 정책 및 메일·일정 도구 계약/코덱을 사용한다.
- Gemma 아티팩트는 같지만 Python LiteRT-LM 0.13.1과 Android 0.16.1의 런타임 버전은 다르다.
- PC 임베딩은 ONNX export, Android는 TFLite다. 벡터/순위/답변 문구까지 완전히 같거나 속도만 다르다고 보장하지 않는다.
- 촬영·EXIF·Android 권한·외부 앱 화면·다운로드는 실기기 검증이 필요하다.
- 기존 `desktop turn`(Gemma 옵션 없음)은 규칙 기반 제어 흐름 테스트이며 실제 모델 평가가 아니다. 이전 `hybrid_server.py`는 별도 구현이므로 현재 통합앱의 동등성 근거로 사용하지 않는다.
- 이 작업은 사용자가 보고한 실패 흐름과 추가 변형을 검증한다. 전체 165시나리오/435턴의 실기기 통과를 주장하지 않는다.

## 증거

첫 실제 모델 로그 `build/desktop-gemma-final.log`에서 이름 유사 후보 혼입과 동일 대상 재검색을 발견했다. 이를 통과로 처리하지 않고 수정했다.
최종 빌드의 실제 Gemma 8턴 검증은 `build/desktop-user-regression.log`에서 통과했다. 도구 종류, 정확한 명함 ID, 회사·부서·전화번호와 이번 검색 결과에 근거한 인물 응답을 검사했다. 추가 5턴도 `build/desktop-tool-transitions.log`에서 통과했다: 문자 → 검색 → 참석자 없는 일정 → 검색 → 전체 명함 수 1,000개. 두 실행 모두 자동 검사기의 `PASS`와 프로세스 종료 코드 0을 확인했다.

`build/desktop-app-policy-final.log`: 단위 테스트 575개, 실패 0·건너뜀 0, debug APK 및 노트북 배포 빌드 성공. 모델 누락 차단 검증은 `build/desktop-missing-model-check.log`: 첫 질의에 진입하기 전에 비정상 종료하는 것을 확인했다.

최종 8턴 실행에서 정확한 필드 조회는 10–26ms, Gemma 검색 설명은 약 27–33초, 메일 초안 도구 실행까지는 약 68초였다. PC CPU 측정이며 폰 성능 수치가 아니다. 불필요한 추론은 줄였지만 생성 자체가 즉시 완료되는 수준은 아니다. 중간 시간 공백으로 중단된 실행은 다시 실행했으며 해당 실행 시간은 성능 수치에서 제외했다.

이번부터 `desktop/`의 실행 소스를 Git 추적 대상으로 전환한다. 모델·APK·DB·로그는 커밋하지 않는다.

S21(SM-G991N)에 최신 debug APK를 `install -r`로 설치했다. 앱 데이터와 모델은 보존했다. `문지영씨 전화번호` 질의 인텐트 수신은 확인했으나, 잠금/알림 화면에 머물러 답변 완료는 확인하지 못했고 이후 기기 연결이 끊겼다. 따라서 이번 변경의 S21 실응답 통과를 주장하지 않는다. 재연결·잠금 해제 후 같은 질의를 확인해야 한다.

기기 앱/모델은 사용자 후속 테스트를 위해 유지한다. 전체 실기기 테스트를 종료할 때 요청대로 제거한다.
