# 서비스형 모델 준비 흐름

## 사용자 흐름

- 첫 실행에서 모형 로그인/토큰 입력/파일 선택 대신 AI 기능 준비 화면을 표시한다.
- EmbeddingGemma 300M과 SentencePiece는 APK 기본 자산이다. 명함 1000개와 사전 벡터 색인도 유지한다.
- 모델 약관·사용 제한·출처 고지는 APK 안에서 오프라인으로 읽는다. 동의 버전을 저장한다.
- Gemma 4 E2B 약 2.59GB만 공개 고정 URL에서 다운로드한다. Hugging Face 계정·토큰은 요구하지 않는다.
- 기본 Wi-Fi만 사용하고, 모바일 데이터는 사용자가 별도로 허용한다. 로밍 다운로드는 허용하지 않는다.
- Android DownloadManager가 화면/앱 프로세스와 독립적으로 전송한다. 재실행 시 저장된 작업 ID로 상태를 복구한다.
- 대기/진행률/검증/실패를 구분한다. 취소하면 해당 다운로드와 임시 파일만 정리한다.
- 최종 크기·SHA-256 검증 후 같은 저장소 안에서 원자적으로 파일을 교체한다.
- 검증과 약관 동의가 완료된 뒤 AI 컨테이너를 생성한다. 수동 강제 종료는 필요하지 않다.
- 모델·다운로드 작업 ID·약관 동의는 클라우드 백업 및 기기 이전에서 제외한다.
- 릴리스 앱은 개발용 질문/이미지 인텐트를 처리하지 않는다.

## 빌드 및 배포

`HJP_MODEL_DIR`에 해시가 일치하는 `embeddinggemma-300m.tflite`, `sentencepiece.model`이 필요하다.
로컬 개발 기본 경로는 형제 폴더 `HJP_limitededition-main/models`이다.
`prepareServiceModelAssets`가 두 파일을 검증하고 모든 빌드 variant의 생성 자산으로 제공한다.
2026-10-04부터 KIE 분류기·토크나이저·라벨의 고정 해시도 함께 검사한다.
파일 부재/변경 시 빌드가 실패한다. 모델 바이너리는 Git에 추가하지 않는다.

## 새 clone의 빌드 준비

APK를 받는 사용자와 소스를 clone해서 빌드하는 개발자의 준비물은 다르다.

| 파일 | APK 포함 | Git 포함 | 개발자 배치 위치 |
|---|---|---|---|
| Paddle OCR det/rec/방향 모델, 문자 사전 | O | O | `app/src/main/assets/ocr/` |
| KIE `kie_minilm_int8.onnx` 36.59MB | O | X | `app/src/main/assets/ocr/` |
| KIE `kie_tokenizer.onnx`, `kie_labels.json` | O | O | `app/src/main/assets/ocr/` |
| `embeddinggemma-300m.tflite` 179.13MB | O | X | `HJP_MODEL_DIR` |
| 검색 `sentencepiece.model` 4.68MB | O | X | `HJP_MODEL_DIR` |
| Gemma 4 E2B 2.59GB | X | X | APK 빌드에는 불필요. 사용자는 앱에서 다운로드 |
| 1,000개 명함·벡터 색인 | O | O | `app/src/main/assets/cards/` |

1. [KIE 자산 안내](OCR_ASSETS.md#kie-반입-출처와-빌드-준비)의 축소 분류기를 받아 배치하고 해시를 확인한다.
2. 다음 두 파일을 **고정 리비전**에서 받아 같은 모델 폴더에 둔다.
   원격 파일명을 앱이 사용하는 로컬 파일명으로 바꾼다. 배포처의 접근 승인이 필요한 경우
   개발자가 취득 절차를 진행하며 앱 사용자에게 계정·토큰 입력을 요구하지 않는다.

| 로컬 파일명 | 다운로드 파일 | SHA-256 |
|---|---|---|
| `embeddinggemma-300m.tflite` | [seq256 mixed-precision TFLite](https://huggingface.co/litert-community/embeddinggemma-300m/resolve/29888fcee3216acadc7e844906e5fe0d79a61875/embeddinggemma-300M_seq256_mixed-precision.tflite) | `37115ef7bff76cd37dd86abe503ff511b1032bf85fc624a85c49c84899e92bc5` |
| `sentencepiece.model` | [SentencePiece](https://huggingface.co/litert-community/embeddinggemma-300m/resolve/29888fcee3216acadc7e844906e5fe0d79a61875/sentencepiece.model) | `d6daa52d93d7aad10e8388bd526c4e501d914b47177398d1d9621f1fe48438c7` |

3. 프로젝트 루트에서 다음을 실행한다. 경로는 실제 다운로드 폴더로 바꾼다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
$env:HJP_MODEL_DIR = 'C:\hjp-models'
Get-FileHash -Algorithm SHA256 -LiteralPath "$env:HJP_MODEL_DIR\embeddinggemma-300m.tflite", "$env:HJP_MODEL_DIR\sentencepiece.model"
.\gradlew.bat :app:assembleDebug
python scripts/check_apk_payload.py
```

release도 `:app:assembleRelease`로 빌드하며 같은 모델 검증을 적용한다.
서명되지 않은 release APK의 자산만 검사하려면 다음을 실행한다.

```powershell
python scripts/check_apk_payload.py --apk app/build/outputs/apk/release/app-release-unsigned.apk --report build/apk-payload-check-release.json
```

`HJP_MODEL_DIR`를 생략하면 형제 `HJP_limitededition-main/models`를 사용한다.
APK에는 검증한 KIE와 임베딩 두 파일이 포함되므로 사용자는 별도로 받지 않는다.
앱의 서비스 다운로드는 `ModelDownloads.generative` 하나만 사용한다.
목록 `required`에 임베딩까지 등록되어 있어도 서비스가 세 파일을 다운로드한다는 뜻은 아니다.

노트북 웹/CLI 실행은 별도의 ONNX 임베딩 export(외부 데이터·tokenizer.json 포함),
Gemma 파일, Temurin Java 21, Python LiteRT-LM을 필요로 한다.
`HJP_EMBED_MODEL_DIR`, `HJP_GEMMA_MODEL`, `HJP_DESKTOP_JAVA_HOME`, `HJP_PYTHON`으로 지정한다.
Android의 TFLite 두 파일만으로 노트북 검증을 실행할 수 없다.

앱에 포함하는 EmbeddingGemma와 토크나이저는 원본 바이트를 유지한다.
공식 Gemma 약관/사용 제한과 Apache-2.0 전문, NOTICE를 `app/src/main/assets/legal`에 포함했다.
상용 출시 전에는 서비스 운영 주체가 약관 적용, 모델별 고지, 서명·스토어 배포 조건을 최종 검토해야 한다.
공개 모델 호스팅의 가용성을 자사 서비스 SLA로 보장하는 구성은 아니며, 전용 CDN을 신규 개설하지 않았다.

## 검증 범위

- 전체 주 회귀 테스트: 564개, 실패 0, 오류 0, 건너뜀 0. 중복되는 release 변형 집계는 제외했다.
- `test :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease` 성공.
  로그: `build/service-model-final.log`. 릴리스 APK는 정식 배포용 서명을 완료한 산출물로 간주하지 않는다.
- APK 검사: 검색 모델 2개 해시, 약관 4개 원문 일치, OCR/명함 자산 11개, arm64 라이브러리 6개, 1000×768 색인 통과.
- `HJP_MODEL_DIR`를 존재하지 않는 경로로 지정한 음성 테스트: `Required bundled model missing`으로 빌드 실패 확인.
  로그: `build/service-model-missing-input.log`. 정상 모델이나 APK는 삭제/변경하지 않았다.

- 고정 LLM URL에 인증 없는 HEAD 요청: HTTP 200, 2,588,147,712바이트 확인.
- 전송 자체는 Android 시스템 다운로드를 사용한다. 실제 폰에서의 전체 다운로드·네트워크 단절/재개·모델 추론 검증은 별도로 기록한다.
- 손상 파일 교체 방지, 시스템 다운로드 승격, 다운로드 대상/번들 구분, 준비 상태와 배포 오류 메시지 회귀 테스트를 추가했다.
- 모델을 PC에서 복사한 결과를 앱 다운로드 검증으로 간주하지 않는다.
- S21 테스트가 종료되면 테스트 앱과 모든 앱 전용 모델을 제거하고, 결과만 PC에 남긴다.

## S21 상태 기록 — 2026-09-16 모델 준비 화면 점검 당시

기존 앱을 제거하고 새 디버그 APK를 설치했다. 첫 실행에서 로그인/토큰 입력 없이 AI 기능 준비 화면이 표시되고,
번들 모델 검사 후 다운로드 준비 상태가 된 것을 확인했다. 오프라인 Gemma 약관 대화상자 표시도 확인했다.
약관 동의는 대행하지 않았다. LLM은 PC에서 복사하지 않았으며, 사용자 동의 후 실제 앱 다운로드 검증을 진행해야 한다.
현재는 테스트 종료가 아닌 동의 대기 상태라 새 테스트 앱을 기기에 남겨 두었다.

이 단락은 당시 기록이다. 이후 설치·다운로드·검증 이력은 해당 인수인계와 실기기 기록을 따른다.
2026-10-04 통합 작업 시작 시 ADB 연결 기기는 없었다. 새 통합본의 S21 실응답·외부 앱 전환,
실제 OCR 사진·권한·다운로드 재개·전체 165시나리오/435턴 실행은 이번 작업에서 미확인이다.
